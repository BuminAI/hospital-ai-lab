      Score table and review rules

      All criteria are public
      1. First it checks whether the upload can be reviewed. It must be a program that contains code that actually runs (scripts in HTML, or JS, Apps Script, Python and the like). PDFs, documents, images and HTML with only a screen are marked "not subject to review," get no score and are not sent to the operator. (It does not decide whether AI made it; it only confirms that it is a program.)
      2. Mandatory requirement: if the code contains a value that looks like an API key, a password or personal data, the grade is not set and the review is put on hold, whatever the score.
      3. 14 items, 100 points at most: safety 35, reliability 30, usability 15, maintainability 10, portability 10. All points are calculated only from facts found in the uploaded code (with file and line evidence); the points and the rule for each item are published below.
      4. The grade is set from the points (S from 90, A from 75, B from 60). If there is a runtime error the grade is capped at B, and if the execution check could not be done, S is not given.
      5. The same code always gets the same score and the same result ID (a fingerprint made from the code and the scoring-rules version). Anything the submitter writes, such as the program name, submitter, department or a manual, is not used in the score at all.
      6. Code read from linked sources (GitHub, Gist, web pages, Apps Script web apps) is reviewed together with the uploaded files. A link that cannot be read adds nothing to the score, and because the review scope is then partial, grade S is not given. The analysis report explains how to unblock it.

      Reward amounts differ by organization, so enter your own. What you enter is saved only in this browser.

      The automatic analysis judges by text-matching rules, so it can miss things or catch the wrong ones. Use the result as supporting material for a reviewer’s judgment.
